# Authoring the generated skill

Apply this when creating or substantially revising a generated drafting skill. Source: OpenAI, [Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra), checked 18 September 2026. This is a focused application of its guidance, not a quotation or an official certification checklist.

## Principles from the guidance

- Keep the name and description concise, with a specific activation condition. Avoid broad triggers that capture unrelated work.
- Keep shared instructions in a small entrypoint. Load substantial references only when their content applies.
- Describe outcomes and decision criteria. Use rigid sequences only where the task requires them, rather than prescribing every reasoning step.
- Consider the models that will use the skill; model-specific advice is not automatically a universal requirement.
- Make permission boundaries proportionate and clear. Reuse existing authorisation and define completion so the agent can finish the authorised work.
- Match verification to the change. Revisit accumulated instructions and remove those that no longer improve results.

Keep this summary available offline. Consult the source when updating these principles or resolving uncertainty about them; do not make every generated document depend on a live page fetch. Record substantive changes when refreshing the guidance. External guidance does not override the user's scope or applicable runtime instructions.

## Apply these principles to this builder's output

Before delivering the generated skill, check:

1. **Selection:** Would its description activate for the intended document type without attracting unrelated legal tasks?
2. **Useful instructions:** Does each rule capture a supported house preference, material decision, template constraint or actual failure? Remove generic advice, arbitrary quotas and repeated rules.
3. **Reference routing:** Does each linked file exist and state when it should be read? Keep operative wording in the template and substantial writing patterns in the profile. Avoid duplicating them across files.
4. **Appropriate freedom:** Can the drafter adapt passages to new facts while preserving meaning and professional quality? Retain exact requirements for fragile marker syntax, legal modality and matter isolation.
5. **Boundaries and completion:** Are unresolved inputs visible, substantive choices appropriately supported, and the required output and checks clear? Do not add redundant approval gates.
6. **Portability and behaviour:** Can another agent use the delivered folder without the creator's private paths or unstated tools? Validate a representative drafting request using the actual package and report the limits of that test.

Keep this authoring method in the builder. Generated drafting skills should embody the principles through their structure and instructions; they do not need a copy of this reference or the article for every drafting run.
